Zombie Lane

Digital Chocolate's zombie-survival builder game. The Android build depended on Facebook login and online services from 2015.

    About the original

    Zombie Lane was a social survival game by Digital Chocolate. It first ran on Facebook, and an Android version followed. You built up your neighborhood while fighting off zombies. Like many social games of its time, it relied on Facebook login and online purchases, so it stopped working when those services shut down.

    Rights status: unknown. Needs research before any assets are reused in a public build.

    All game logic is Java bytecode, so REA's Android (JADX) tools cover it. The native libraries are only used for AllJoyn local multiplayer.

    Findings

    • Main loop: one logic update per rendered frame, with a variable time step. dt is the average of the last 8 frame times, each capped at 500 ms. architecture.md
    • Rendering: everything draws through a J2ME-style 2D Graphics API in an orthographic projection, so it maps directly onto Canvas 2D.
    • Saves are local: the home scene and missions are stored as J2ME RecordStore records, and the built-in neighbor "Rob" loads locally. The core game likely works offline (still to confirm).
    • Data formats decoded: an indexed table container (u32 size, u32 count, u32 offsets), 32-bit resource/text IDs (file number + index), and readUTF strings. resource-formats.md
    • Online: the game's own XML "servlet" API on a now-gone EC2 host only handled sessions, cloud save, timers and social features. Facebook, payments, ads and analytics become stubs. online-dependencies.md

    Rebuild plan

    1. Analysis: map the game loop, save format, building and zombie rules, and asset archive layout.
    2. Offline rules: swap every online dependency (login, purchases, friends, offers) for local state.
    3. Rebuild: write a Canvas/TypeScript version from the specs. Players load the original art from their own APK in the browser. Nothing is uploaded or hosted here.
