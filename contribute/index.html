Add a project to the list

The whole list is one JSON file in our public repository, github.com/a-barzanti/ai-rebuilds. You can suggest a project without touching code, or add it yourself with a pull request.

The quick way: suggest it

Open the suggestion form on GitHub. It asks for a link, what the project rebuilds and how. A maintainer checks it and adds it, usually within a week.

Add it yourself

  1. Open data/projects.json on GitHub, or fork and clone the repository.
  2. Add an object to "projects", using the fields below. Set "added" to today's date, and set "updated" at the top of the file to the same date.
  3. If you're working locally, run bun run sync. It regenerates the list in index.html and README.md. Then run bun run check.
  4. Open a pull request. If you edited on GitHub and can't run Bun, say so in the pull request and a maintainer will run the sync for you.
{
  "id": "openrct2",
  "name": "OpenRCT2",
  "category": "game-engines",
  "rebuilds": "RollerCoaster Tycoon 2",
  "summary": "A full reimplementation of the game. Uses the data files from your copy.",
  "ai": "none",
  "method": "reimplementation",
  "url": "https://openrct2.io",
  "repo": "https://github.com/OpenRCT2/OpenRCT2",
  "added": "2026-10-29"
}

Fields

FieldWhat to put
idLowercase with dashes. It becomes the link anchor, for example ai-rebuilds.com/#openrct2.
nameThe project's own name.
categoryOne of craft, ai-software, ai-games, game-engines, decomp, clean-room, tools. If none fits, propose a new one in your pull request.
rebuildsWhat the original is, for example "Adobe Photoshop" or "Super Mario 64 DS (Nintendo DS, 2004)".
summaryOne or two plain sentences in your own words, under 280 characters. Don't paste the project's README.
aibuilt if agents wrote most of it, assisted if people did and AI helped, none if no AI was used, unknown if the authors don't say.
methodclean-room, reimplementation, decompilation, recompilation, port, rewrite or tool.
url, repo, writeupOptional https links to the website, source code, and the best article about it. At least one is required. GitHub repos get stars and activity filled in automatically.
year, byOptional. The year it started and who made it.
addedToday, as YYYY-MM-DD.

Leave out github. The weekly refresh fills it in.

What gets in

  • It rebuilds something that already exists: an app, an engine, a protocol or a game. Projects that are only "inspired by" something belong elsewhere.
  • It's public. There is source code, a usable build or at least a detailed write-up.
  • It doesn't distribute the original. Leave out projects that host the original's code, binaries, ROMs or assets, or link to pirated copies. Decompilations and engines that need your own copy are fine.
  • It's honest about AI. Label AI involvement the way the authors describe it, and link to their write-up if there is one.

Being listed doesn't mean we endorse a project or have checked whether it's legal. If you hold the rights to an original, or maintain a listed project, and want an entry changed or removed, open an issue. We act on it promptly.

How the list stays current

A GitHub Action runs every Monday. It updates stars, last-commit dates and archive status for every listed repository, follows repositories that have moved, checks the other links, and republishes the site. The date at the top of the home page shows when the list itself last changed.

Running the site locally

The site is plain HTML, CSS and JavaScript with no build step. You need Bun for the scripts.

bun run dev       # http://localhost:3000
bun run sync      # regenerate index.html and README.md from the data
bun run check     # validate the data, check the generated files are up to date
GITHUB_TOKEN=$(gh auth token) bun run refresh   # what the weekly job does
