Make your own rebuild with REA

REA gives a coding agent the tools to study software it doesn't have the source for. It can work with Android APKs, native binaries, .NET, Electron apps and web pages. Every finding comes back with the evidence behind it, so the agent can write a spec you can check.

The DX-Ball reconstruction in the list was made this way. Our guide shows the clean-room version of the workflow. One agent studies the original and writes specs. A separate one writes new code from those specs alone.

Read the REA guide REA on GitHub 
# Ask the agent, with REA connected:
Analyze ./game.apk with REA. Map the app
structure, the main loop, the asset formats
and every online dependency. Write specs of
behavior and formats. Cite evidence IDs and
don't copy decompiled code.

Add a project to the list

The list lives in one file in our public repository, github.com/a-barzanti/ai-rebuilds. Anyone can suggest or add an entry.

  1. Suggest it

    Fill in the short suggestion form on GitHub. You don't need to write any code. A maintainer adds it.

  2. Add it yourself

    Edit data/projects.json, run bun run sync and open a pull request. See the steps and fields.

  3. Fix an entry

    Is a link dead, or a description wrong? Report it. If you maintain a listed project and want it changed or removed, use the same form.

A project gets in if it's public, rebuilds existing software or a game, and doesn't distribute the original's code, binaries or assets. Being listed doesn't mean we endorse a project or have checked its legal status.
