Open source · Community-run · Built with REA

Abandoned games, rebuilt for the open web.

Many old games no longer run because their platforms, stores or servers shut down. Here, contributors use AI agents and REA to work out how each game behaves. Then they write a new version that runs in any browser.

How a rebuild works

  1. 01

    Pick a game

    Choose a game that is abandoned or no longer runs anywhere. Open a project with its history, the platforms it ran on, and what is known about how it was built.

  2. 02

    Analyze with REA

    An agent connected to REA examines your own copy of the game, whether it is a native binary, an APK, a .NET build, Flash or WASM. Every finding cites its evidence. You write the findings up as specs.

  3. 03

    Rebuild for the web

    Write new code from the specs, not from decompiled source, using whatever web stack fits the game. Players load the original assets from a copy they own, or the project uses newly made assets.

  4. 04

    Verify and ship

    Check the rebuild's behavior against what was recorded from the original. When it is playable, it goes live on this site.

Ground rules

  • No original files here. Do not commit game binaries, ROMs, APKs or extracted assets. The .gitignore blocks the common file types.
  • Specs, not stolen code. Commit findings, notes and specs. Do not commit dumps of decompiled source.
  • Bring your own copy. A rebuild loads original assets from the player's own files, or uses newly made assets.
  • Rights holders come first. "Abandonware" has no legal meaning. If a rights holder objects, the project comes down. No arguing.
